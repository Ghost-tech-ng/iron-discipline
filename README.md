# Iron Discipline

Offline-first fitness transformation app built with React Native + Expo — single-user by design, with an AI coach and AI-assisted meal logging built in.

## Architecture

- **Expo Router** for file-based navigation across a 5-step onboarding flow and a tabbed main app (workouts, nutrition, habits, progress)
- **Zustand** for state, split into ten domain stores (`workout`, `nutrition`, `discipline`, `habit`, `progress`, `sync`, `theme`, `shoppingList`, `customFood`, `user`) rather than one global store
- **expo-sqlite** as the local data layer — the app is fully usable offline with no backend
- A dedicated **sync layer** (`services/syncService.ts` + `store/syncStore.ts`) reconciles on-device state with a MongoDB-backed service (`services/mongoService.ts`) when connectivity allows, with a visible sync status indicator in the UI rather than a silent background process
- An **AI service** (`services/aiService.ts`) drives two features: a conversational coach (`components/ai/CoachCard.tsx`) and AI photo-based meal logging — the user photographs a plate and the app estimates macros (`app/meal/scan.tsx`)
- **Barcode scanning** (`services/barcodeService.ts`) for packaged food logging
- **NativeWind** (Tailwind for React Native) + **Moti** for animation, `expo-haptics` for tactile feedback on key interactions

## Features

- Guided onboarding that turns biometrics and a stated goal into a personalized macro and training program
- Workout logging with per-set tracking and rest timers
- Nutrition logging via search, barcode scan, or AI photo scan
- A daily discipline score — the percentage of the day's program actually executed, reported as fact rather than framed as a gamified streak
- Progress analytics: weight, strength, calorie, and discipline-score charts
- Offline-first with background sync and a visible sync status bar

## Why it's built this way

Most fitness apps are built for mass-market retention — feeds, streaks, badges. This one is built for a single user running a single program: no social layer, no gamification noise. Every screen is built around one outcome — making the plan easier to execute and harder to skip — and the discipline score is a measurement, not a motivational device.

```bash
npm install
npx expo start
```

The section below is genuine output from the app's personalization engine, not placeholder text — it's included to show the depth of the domain logic (science-based macro targets, a research-backed training split, and a structured supplement protocol), not as personal health documentation.

### Nutrition targets

Macro and calorie targets are derived from peer-reviewed sports nutrition research (Helms et al. 2014; Phillips & Van Loon 2011) based on bodyweight, goal, and training level — protein set at the upper end of the recommended range (2.0–2.2 g/kg) to preserve lean mass during a fat-loss phase, calories set to a moderate deficit against estimated TDEE.

### Training split

A 5-day Push / Pull / Legs / Upper / Lower split, hitting every muscle group twice per week — the frequency shown by Schoenfeld et al. (2016) to outperform once-weekly splits by ~3% in hypertrophy outcomes across a meta-analysis of 10 studies.

### Supplement protocol

A minimal, evidence-based stack (creatine monohydrate, whey, omega-3, vitamin D3, magnesium glycinate) with dosing and timing rationale for each.

This is the kind of structured, cited domain logic the onboarding flow turns into a live program — the app's job is encoding it once and then adapting it to daily execution data.
